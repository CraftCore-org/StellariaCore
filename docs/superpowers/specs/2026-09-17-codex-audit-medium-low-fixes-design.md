# Codex監査 Medium/Low 修正 Design

**目的:** 2026-09-17 の監査で指摘された Medium 10 件と Low/Improvement 5 件を、既存の機能契約を変えずに是正する。

## 方針

既存のコマンド、マネージャー、ユーティリティに局所的な責務を追加する。新しい常駐基盤や設定形式は導入しない。`/stellariareload` は設定を保持するマネージャーと定期タスクを再設定するが、Vault、Discord/JDA、イベントリスナーの接続・登録は再生成しない。

## テレポートと退出時状態

- `TeleportSafetyUtil` は、危険地点の警告、テレポート成功、テレポート失敗を区別して返す。`Player#teleport` が `false` の場合は、成功演出を行わず確認状態も消費しない。TPA とエレベーターも戻り値が `true` の時だけ成功演出・成功メッセージを送る。
- `HomeCommand` と `WarpCommand` は UUID を受け取って自身の確認待ち状態を削除できるようにする。
- `PlayerListener` の退出処理から、ホーム／ワープの確認待ち、PMの返信先、メニューアイテムのクールダウンを削除する。

## 設定と定期タスク

- `ConfigFile` は設定オブジェクトを `volatile` 参照として安全に公開し、reload 時に完全に構築済みの設定だけを原子的に差し替える。
- `ConfigManager` の messages.yml 向け getter は、欠落警告にも実際のファイル名 `messages.yml` を使う。
- 文字列のパーティクル名は共通の安全な解決処理を通す。不正な値は警告を1回出して `DUST` へフォールバックする。join、home、warp、TPA の演出に適用する。
- 設定由来のスケジューラ期間は、ゼロ・負値を最小の 1 tick に丸める。分→tick の換算は最初から `long` で行い、整数演算のオーバーフローを防ぐ。
- `StellariaCore` は設定をキャッシュする HUD/ActionBar/BossBar と、設定により開始・停止・周期が変わる定期タスクを再設定できるようにする。リロードで auto broadcast、world reset、head shop、land border、HUD 更新タスク、ActionBar/BossBar の設定を反映する。イベント登録や外部接続の再初期化はしない。
- reload 成功／権限不足のメッセージは `messages.yml` に移す。

## 経済・ランキング・投票・mute

- 新規プレイヤー行は `INSERT OR IGNORE` で同期的に確保する。参加直後の経済更新は、0行更新を成功として返さない。
- 所持金ランキングは `hide_balance = 0` を SQL の件数・取得の両方に含め、公開エントリだけをページングする。表示順位は公開ランキング内の順位とする。
- 時間・天気投票の賛否は、投票開始時に記録した `World` と一致するプレイヤーだけ受理する。対象外ワールドには既存の world-disabled メッセージを使う。
- mute は相対秒数と epoch milliseconds の加算に `Math.multiplyExact`／`Math.addExact` を使い、表現不能な有限期間を拒否する。`perm` だけが永久 mute を表す。

## スコアボード共存

`BoardUtil` はメインスコアボードでないボードを無条件に引き継がない。Stellaria が作成・割当した個人ボードだけを再利用し、他プラグインが割り当てた個人ボードには objective/team を登録しない。対象プレイヤーについては表示更新をスキップし、他プラグインの表示を壊さない。

## 検証

- 新規ユーティリティと純粋な境界値ロジックには JUnit テストを先に追加する。対象は期間のオーバーフロー、スケジューラ値の正規化、パーティクル解決、確認状態のクリーンアップ、および公開残高のページング条件。
- Paper API に密結合する処理は最小限のテストダブルで戻り値・状態遷移を検証し、難しい箇所はビルドと既存テスト一式でコンパイル互換性を確認する。
- 最終確認は `./gradlew test` と `./gradlew build` を実行する。
