# チェストロック・テキスト表示・UI基盤の堅牢化

- 日付: 2026-09-17
- ステータス: 実装前レビュー待ち

## 目的

チェストロックの永続データと実際のワールド状態の不整合をなくし、ロック操作の通知を一貫してチャットへ出す。
併せて、アイテム名・説明文の既定スタイル、Discordプロフィールの色コード漏れ、HUDとGUIの監査で確認した再現可能なUI不具合を修正する。

## 対象範囲

### コンテナロック

- 共同利用者がいないロックでも、`/unlock` と最後のロック対象ブロック破壊で正常に削除できるようにする。
- 所有者と、明示的に `/lock bypass` を有効にした管理者は、ロック済みコンテナを直接破壊できる。ブロック破壊が最終的に成功した後、対象座標をロックから外し、最後の座標ならロック本体・共同利用者も削除する。成功時はチャットへ自動解除通知を出す。
- 権限のないプレイヤーの開閉・破壊・二連化はキャンセルし、保護通知をチャットへ送る。
- ロック機能が現在 `ActionBarManager` に出す一時通知と bypass 常設表示を廃止し、すべて `messages.yml` 経由のチャット通知へ統一する。
- `/lock` は、対象座標すべてについて土地の建築権限を必要とする。個別ロックは土地保護を迂回しない。
- `/unlock` は引数なしだけを受け付ける。余分な引数は利用方法を表示し、状態を変えない。
- `/lock bypass` の一時状態はログアウト時に破棄する。

### ロックのデータ整合性

- SQL更新を「必ず1行以上変更」とは扱わない。共同利用者が存在しない場合の `DELETE` は正常な削除としてトランザクションを継続する。一方、ロック作成・座標追加など、重複を検出すべき書込みは期待件数を検査する。
- 破壊後の削除は、イベントが最終的にキャンセルされなかったことを `MONITOR` 段階で確定してから次 tick に行う。破壊済み座標に新しいロック可能ブロックが置かれていても、古いロックを残さない。
- 起動時にDBからロードしたロックをワールド状態と照合する。対象ワールドが存在しない、対象座標がロック対象外、二連チェストの左右が別 `lock_id` の場合は、DBとキャッシュから矛盾した座標を取り除く。片側だけが有効な二連チェストは、既存の有効なロックを維持しつつ、無効側を削除する。
- ワールドリセット前後に、対象ワールドの `container_lock_blocks` と空になったロック本体・共同利用者をトランザクションで削除し、マネージャーのキャッシュも同じ範囲で破棄する。新しいワールドが旧座標のロックを継承しない。

### アイテム名・説明文とDiscordプロフィール

- `/setname` と `/setlore` は、各入力行を白 (`&%f`)・非 italic を継承可能な既定スタイルとして扱う。ユーザーが後ろで指定するレガシー色、カスタム色、HEX色、または italic を含む装飾は上書きしない。
- Discord `/profile` の非公開残高はMinecraftの legacy/HEX カラーコードを含まないプレーンテキスト `非公開` とする。Discordへ送る値は表示境界でAdventureのプレーンテキストへ変換する。

### UI監査で確認した不具合

- `ActionBarManager` と `BossBarManager` のチャンネル状態を、リージョンイベントとグローバル tick から安全に同時利用できるようにする。表示順とTTLの意味は維持する。
- `nametag.enabled` をリロードで無効化した時、プラグインが追加したランクチーム・エントリを除去する。
- 永続アクションバーをリロードで無効化した時、全オンラインプレイヤーの `persistent` チャンネルを除去する。
- 親画面から開くワールド選択画面は、最終スロットを戻るボタンとして常に予約する。
- URLハイライトは、URL内部の対応した丸括弧・角括弧を保持し、文末に余分に付いた対応しない句読点・閉じ括弧だけをリンク外へ出す。

## 設計

### ロック削除と通知フロー

```text
BlockBreakEvent
  ├─ 所有者 / 有効化済みbypass管理者: 許可
  │    └─ MONITORで未キャンセルを確認 → 次tickにDB+cacheから対象座標を削除 → チャット通知
  └─ その他: キャンセル → チャットの保護通知
```

`ContainerLockManager` は、操作の意味に応じたSQL実行ヘルパーを持つ。削除操作は0行でも成功として扱い、作成・追加操作は一意制約または期待変更件数により失敗を検出する。DBトランザクション成功後にだけキャッシュを更新する原則は維持する。

破壊のクリーンアップはブロック種別から「破壊されなかった」と推測しない。イベントの最終キャンセル状態を使うことで、同tickの置換コンテナを旧ロックの継続と誤認しない。

### 起動時・ワールドリセット時の整合性

DBロード後、利用可能なワールドと各座標の実ブロックを検証する。無効座標をロックから外し、空ロックを削除する。二連チェストの2座標が異なる `lock_id` に紐付く競合は、所有者・共同利用者の取り違えを防ぐため、両方の座標関連と空になったロックをDB・キャッシュから除去して、所有者に再ロックを要求する。修復内容は管理者が追跡できる警告ログを残す。

`WorldResetManager` はリセット対象のワールド名を `ContainerLockManager` へ渡し、同じトランザクション境界で座標・空ロック・共同利用者を掃除してからワールドを再生成する。

### チャット通知

`ContainerLockMessages` を通知の唯一の入口とする。リスナーは `ActionBarManager#flash` / `setChannel` を呼ばず、現在と同じ `lock.*` 文言をプレイヤー宛チャットとして送る。bypassの有効・無効も既存チャット通知だけを残し、ActionBar常設インジケータは削除する。新しい文言が必要な場合だけ `messages.yml` に追加する。

### 表示スタイルとDiscord境界

`ItemTextUtil` はカラーコードをComponentへ変換した後、色・italicが未指定の部分だけに白と `italic=false` を補う。明示的な色・italicなどの子スタイルには介入しない。

Discord Embedへ渡す値はMinecraftカラー文字列ではなく、Adventure Componentから直列化したプレーンテキストを使う。これにより既存の `messages.yml` の色指定を変更せず、Discordには装飾コードが出ない。

### UI基盤

ActionBar/BossBarは、チャンネルの追加・削除・期限切れ整理・反復を一つの同期境界に収める。tickは同期中に送信用スナップショットを作り、ネットワーク送信はロック外で行う。これにより順序を保持しつつ長時間ロックを避ける。

Nametagは無効化遷移でプラグイン所有のチームを消去する。永続ActionBarは無効化遷移で`persistent`チャンネルを全員から消す。WorldSelectGuiは親画面を持つ時のページ容量を戻るスロット分だけ減らす。

## エラー処理と後方互換性

- DB削除や起動時修復に失敗した場合、キャッシュを先に変更せず警告ログを出す。通常のプレイヤー操作は成功済み永続状態だけを参照する。
- 起動時に未ロードのワールドは削除対象ではなく、警告して次のワールドロード時に再照合できるようにする。意図的に一時アンロードされたワールドのロックを失わないためである。
- `/lock` の既存権限、ロック対象ブロック、共同利用者の意味は変えない。
- `messages.yml` の既存ロック文言は名称を維持し、ActionBarからチャットへ配信経路だけを変更する。

## テストと検証

JUnitで少なくとも次を回帰テスト化する。

- メンバーなしロックの解除・最後の座標削除、およびキャッシュ/DB削除判定。
- 所有者/bypass管理者と非権限者の破壊判定、`/unlock` の余分な引数。
- 破壊直後の同tick置換で旧ロックを削除する状態遷移。
- 土地建築権限がない `/lock` の拒否。
- ログアウト時のbypass破棄。
- 非italic白の既定アイテム名・複数行lore、明示色・明示italicの保持。
- Discord向けプレーンテキスト変換。
- ActionBar/BossBarの並行更新、永続ActionBar/Nametagの無効化クリーンアップ、WorldSelectGuiの戻る枠、対応括弧入りURL。

最後に `./gradlew test` と `./gradlew build` を実行する。ロックのイベント境界、二連チェスト、ホッパー、土地保護、ワールドリセットは `./gradlew runServer` で所有者・共同利用者・bypass管理者を含む手動確認を行う。
